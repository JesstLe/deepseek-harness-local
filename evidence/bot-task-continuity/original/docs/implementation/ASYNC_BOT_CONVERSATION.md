# 异步员工协作

## 目标与边界

用户把工作交给主管后，主管在任务持久化受理后先确认，运营继续在独立任务 Session 工作。用户可以继续在主管的接待会话讨论其他话题；结束回复、换话题或切换员工不会调用目标任务的取消接口。完整头像/角色模型不是本切片内容，本轮只提供真实工作态的轻量动效。

## 数据与执行归属

- `BotTaskStore` 管理任务、状态、回复模式及持久化 outbox，Session 仍拥有实际执行与消息收据。
- 新派单 `replyMode=background` 缺省；已落盘但没有此字段的旧任务继续按旧 wait 模式回传，不重写历史任务。
- 执行中的员工向下一位员工派发依赖任务时缺省 wait，避免把“交代出去”当作本职任务完成；接待会话默认 background。
- 同一幂等键不能改变目标、正文、输出类型或回复模式。多个任务有各自 task ID、target Session 和消息 ID；不把新话题拼入旧任务要求。
- 原有文件交付、权限、模型和成员身份校验继续复用。旧幂等键重试缺省沿用原任务 replyMode，避免升级后误报冲突或重复派单。

## 接话与等待

`bot_dispatch` 在本地任务受理落盘后返回；不等目标完成。模型提示明确要求：简短确认并结束当前回复，不调用 wait/get/list/sleep 循环等待。

若模型仍对后台任务调用 `bot_task_wait`，缺省直接返回当前任务及 background 提示，不挂起一个等待器。用户明确要求等结果时，可派单 `replyMode="wait"`，或者使用 `bot_task_wait(waitForResult=true)`。这不是取消后台任务，也不会自动重派。

```js
bot_dispatch({targetBotId:"bot-<实际目录 ID>",task:"生成活动文案",output:"files",idempotencyKey:"campaign-01"})
// 受理后先回复用户；目标任务独立执行。
```

## 不打断当前话题的结果回传

后台任务向主管回传时使用原生 `agent.followup` / next-turn inbox，而不是 `steer` / next-step。主管正处理新话题时，结果先进入下一轮队列，不改变当前模型步骤；闲置时由原执行器唤醒处理。消息继续是 `agent-message/relay`，携带原 task ID、来源和任务正文，不冒充新用户指令。

同一回传消息 ID 的收据和 pending 队列继续去重；重启后不重复执行已消费任务，也不把等待下一轮的结果强行移到当前步骤。主管回复原任务结果时仍需区分执行完成与业务验收，不擅自取消、重写其他任务。

下一轮通知遵守原生队列顺序，并非把每条结果实时插入用户当前正在读的回复。源会话当前模型调用本身仍使用原执行器；本切片不承诺一个会话同时跑多个模型回合。

## 前端

- 在原生 `conversation.input.dock` 追加轻量任务卡，不替换会话、输入器、模型选择或队列控件。任务卡依照源/目标 Session 归属筛选，与正在讨论的话题草稿互不覆盖。
- 共享一个 owner HTTP + SSE 订阅，为任务卡与侧栏提供真实排队、准备、工作、待确认、完成和异常状态。读取紧凑 `?view=activity` 投影；展开详情时再读对应任务，避免把整个结果账本反复传给所有组件。
- 卡片可查看执行会话、展开成果、打开原生文件预览或显式停止单项任务。停止操作仍走真实权限/CAS；只有执行停止成功才记 cancelled，失败后可再次操作，不误报已停止。
- 点击员工默认进入非派单的接待 Session，优先员工 home 会话；明确点击任务卡或任务记录才进入执行上下文。没有可用接待会话时，点击员工显式创建并关联新会话。
- 头像仅在真实 working 状态显示轻量动效，排队和待确认分别展示；支持系统减少动态效果。离线/权限丢失不制造任务或虚构进度。
- 三张以上卡片可展开全部，任务区限定高度；长结果按需展开，保持聊天输入区域可用。

### 任务卡回收

输入区只保留当前任务与短时结束回执。排队、准备、运行、待确认及未知状态继续显示；完成、失败、取消、中断在 `updatedAt` 后 8 秒收进“任务记录”，打开页面时过期旧卡片不再展开。正在阅读的详情暂停自动回收，收起详情后恢复；终态卡片也可手动关闭。收起只影响展示，不删除任务、文件或结果，不取消执行。

本地偏好以 ID/attempt/status 为键，最多 500 条并同步同源标签页；刷新仍保留手动收起状态，重试的新 attempt 自动重新出现。任务记录默认仅一行入口，异常数保留；展开后按 10 条逐步加载，可继续查看执行会话、原结果与文件预览。仅使用一个最近到期 timeout，不为每张卡建立轮询。见 [任务卡回收记录](../changes/2026-11-17-task-card-recycling.md)。
