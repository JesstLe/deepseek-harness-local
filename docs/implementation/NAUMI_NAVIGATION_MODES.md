# 线程 / Bot 双模式

## 用户决策

2026-11-16：保留原线程模式，同时增加可以切换的 Bot 模式。Bot 像可重复交办工作的电子员工，而不是给每条会话换一个头像。名称与组织继续由 Agent 自主管理。

## 设计契约

- 默认线程模式；模式只改变左侧工作区列表的呈现，原有业务导航、会话、输入草稿、模型和权限不变。
- 模式选择使用本机视图偏好 `naumi.navigationMode.v1`，只由用户切换时写入；失效值回到线程模式，禁用存储时仍能操作。
- 线程树保持原位挂载，仅在 Bot 模式隐藏；不替换原组件、store、inject、locale 或子 slot 声明。切回后展开状态、菜单、搜索和会话导航继续工作。
- Bot 目录是明确创建的常驻身份，使用独立 bot UUID。一个 Bot 可关联多个根会话，临时子智能体不自动成为员工。
- 不用会话标题替代 Bot 名，不预置团队类别或岗位别名，不自动把历史会话转换为 Bot。
- 点击 Bot 打开其当前运行任务或最近可打开的任务；任务记录在该 Bot 内部展开。
- “新任务”调用原 session.create（沿用工作区 / preset），随后绑定身份；不发送 prompt、不启动模型、不改变其他会话。绑定冲突保留新会话，重试关联复用同一会话，避免重复创建。
- “创建 Bot”只在原会话草稿中放入创建意图，用户填写需求并发送后，由 Agent 调用 bot_create 自主命名和保存。
- Bot 归档仅影响目录和新绑定，不取消运行任务、不删除会话。原会话仍在线程模式可见。

## 实现

### Host

- `bots.js` 保存 `${DSH_HOME}/naumi/bots.json`，首次创建 Bot 时才落盘；原子临时文件写入 / fsync / rename，成功后发布目录变化。
- `bot_directory / bot_create / bot_update / bot_use` 按原 Team 的精确 Agent 身份注册。创建与修改仅 Lead 可用，成员可读。
- CAS revision 保护修改；一个根会话只归属一个 Bot，跨工作目录绑定被拒绝，子 Agent 不可注册为根任务。
- 本机目录沿用 Harness owner 登录态；GET 读取、SSE 更新；浏览器只能在显式“新任务”操作中绑定已有身份，没有浏览器重命名接口。
- Bot purpose 注入已绑定任务的上下文，身份在不同任务之间稳定；它不授予工具权限，不等于完整历史自动共享。

### Client

- `bot-sidebar.js` 通过 `shell.overlay` 的附加功能位和 React portal，在原侧栏容器加入视图切换与 Bot 目录；不重复注册 `sidebar.workspaces` 或它拥有的子功能位。
- 实际集成发现原框架禁止两个父注册重复声明相同子功能位，因此放弃父 slot 重新注册方案。现方案保留整个原树和声明所有权，按真实 DOM 容器添加 / 清理展示标记；观察器检测目标失联时才重新查询，避免流式输出时反复扫描。
- `bot-sidebar-model.js` 管理共享目录订阅、模式校验、稳定头像、真实运行状态、会话归属和原生新建参数。
- 左侧和右侧共用一份目录源：一个 GET / SSE 连接，按订阅者数释放，不循环轮询。
- 右栏优先显示已绑定 Bot 身份；未绑定时继续使用本轮已实现的 Agent 团队资料。
