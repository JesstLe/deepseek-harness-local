# 本地主动执行 D4：复用与依赖拆解

日期：2026-11-17。状态：调研方案已实现为共享消费器local-owner策略，当前验收见 [实现记录](LOCAL_PROACTIVE_EXECUTION.md)；以下调研时点原记录保留。关联：docs/prd/DAILY_EMPLOYEE_PRIORITY.md。

## 模块与职责

本阶段企业模块保持现状；主动工作使用本地Bot/目标、用户显式批准、原模型和工具权限。不得以删除managed-session/签名授权判断的方式让企业run_agent退化成普通执行。

## 公共接口、依赖方向、状态归属

1. 原生 @deepseek-ai/dsh-schedule 已有Host级持久提醒、既有Session恢复、定时器、最迟一次周期选择、投递收据与持久化ACK。它可以作为日历触发/提醒来源；投递ACK不是工作完成或副作用回执。
2. 现有 EmployeeActivityStore 已有窗口/冷却/累计上限、规则批准nonce、原子队列和clock高水位；继续拥有本地主动规则与排队状态，不新增第三套定时任务账本。
3. 现有 EmployeeProactiveAi 已有AgentLoop消费、人工优先、单规则未结束限制、模型次数/时长、持久UNKNOWN与停止。其 run_agent 当前明确依赖企业task、runtimeGate和naumi-enterprise网关，尚不能作为无需企业登记的本地主动AI。
4. 后续应在原消费器引入显式local-owner策略适配层，与原企业managed策略分域。共用同一队列、原执行器和最终工具guard；本地绑定固定Bot/Session/目标及既有模型选择。企业原策略、授权与预算不改。
5. 本地请求/Token/时长/并发上限可由程序约束；只有实际供应商usage时记实际用量，缺usage保持unknown，不将本地估算标为权威费用。不能静默切模型、扩大preset权限或自动装新工具。

## 待实现验收矩阵
