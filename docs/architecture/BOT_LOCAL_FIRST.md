# Bot 本地优先与服务端故障设计

状态：架构决策 / 待分模块实现。日期：2026-11-16。

## 1. 决策

采用“本地完整运行时 + 服务端组织权威与同步 + 独立模型通道”。服务端不是每次读取记忆、打开会话、执行本地任务的必经点。桌面不是薄客户端。

当前已实现的是本机 Bot 目录、Session、任务账本、outbox、同机 Bot 通信与重启恢复；当前持久化主要是本机 JSON/Session 文件。本文的分层记忆、动态人物设定、跨设备同步、离线授权和模型通道冗余属于新增设计，不把它们记为已上线。

## 2. 本地与服务端的职责

### 本地负责持续运行

- 完整桌面 UI、原生浏览器、插件和本机工具执行器。
- 稳定 Bot 身份/岗位/性格/人物设定的版本化可运行副本。
- 本机任务与会话账本、当前步骤、结果、消息收据、outbox。
- 经授权预取的长期记忆、项目知识、文件及本地检索索引。
- 离线新增的会话、经验、偏好、人设候选变化与草稿；先本地持久化，再同步。
- 本机 Bot 通信、事件驱动任务调度、运行与工作巡检。
- 最近一次有效的签名配置包和离线授权；凭证放入 OS 密钥存储，不放在记忆或人设中。

建议逐步把本机结构化账本迁到 SQLite WAL，附件独立存储，全文检索先采用本地索引。向量检索不是离线启动的硬依赖；索引可重建，事实记录不能只存在于索引中。

### 服务端负责组织权威

- 企业账号、组织成员、设备登记、角色与资源授权、撤权及凭证签发。
- 企业/项目共享知识的权威版本、Bot 岗位与核心设定的发布版本。
- 多设备同步、版本协调、审计汇总、备份和组织级预算。
- 跨设备/云端 Bot 的消息中继与全局任务分配。
- 需要企业权威确认的业务提交、审批与验收结果。

“服务端权威”指共享状态的最终确认权，不表示本地每次使用都必须请求服务端。服务端读写故障时，本地授权范围内的工作继续形成待同步事件，而不是丢弃或伪称已获企业确认。

### 模型通道单独部署

- 业务控制中心和模型网关分离故障域，不共用唯一进程/唯一主机/唯一故障入口。
- 企业托管网关提供独立的高可用入口；单独域名或独立容器本身不等于高可用。
- 供应商确实支持短期、受限、可计费约束的客户端凭证时，可以由企业预授权直接模型通道。
- 不把公司级共享主密钥打进员工安装包。预算和令牌限制由网关/供应商执行，而不是只信客户端计数。
- 可选本地模型承担离线推理；按设备能力下载与验收，不假设全部员工电脑已具备模型和算力。
- 切换模型或计费路由受预先发布的路由策略约束，不因故障悄悄改用更贵模型。

## 3. 数据权威与同步规则

| 数据 | 本地行为 | 服务端行为 |
| --- | --- | --- |
| Bot ID、组织身份、权限 | 缓存已签名版本，不自行扩大权限 | 登记、发布、撤销与审计 |
| 性格与人物设定 | 保留可运行版本；低风险会话适应以增量事件记录 | 保存跨设备发布版本，协调冲突 |
| 经历、偏好、经验 | 先写本地；记录来源、作用范围和确认状态 | 备份、同步；共享晋升按组织规则确认 |
| 项目事实与企业知识 | 使用有权限的缓存，标记版本与最后同步时间 | 维护权威数据与访问范围 |
| 任务与执行收据 | 本机执行日志与结果先落盘 | 全局任务视图与调度归属 |
| 财务、发布、授权等业务结果 | 保存草稿/请求与幂等标识，不伪造远端成功 | 返回实际业务回执与审批状态 |

每条同步事件包含 eventId、tenantId、botId、deviceId、aggregateId、baseRevision、kind、source、payload 与发生时间。事件用唯一 ID 去重，应用与确认分开。

- 新经历可按来源追加合并；事实矛盾保留不同证据并标记冲突。
- 人设低风险变化可以在已授权本地生效并待同步；同一字段的并发变化保留差异。
- 权限、岗位、金额和验收决定不使用简单“最后写入覆盖”。
- 删除使用可同步的删除标记；索引与缓存随之更新。记忆删除与原始会话保留策略分开。
- 共享数据按权限预取和按需缓存，不把整个企业知识库无差别下载到每台电脑。

## 4. 故障时的行为

### Naumi 控制中心故障

已登记设备使用有效的离线授权与本地副本启动；档案、记忆、人设、历史、本机队列与同机 Bot 路由继续运行。独立模型通道和凭证有效时继续推理。跨设备消息入 outbox，等待服务恢复；需要新授权或企业实时确认的操作等待联机。

### 模型通道故障

本地数据、调度和已授权确定性步骤保持可用；模型步骤等待可用路由。存在预配置且通过验收的本地模型时按路由策略降级，否则保留现场与待办，不报告虚假完成。

### 设备完全断网

使用已有的授权缓存和已下载资料。云模型、跨设备协作、在线业务提交等待网络恢复。本地推理取决于本地模型是否已安装且满足任务能力要求。

### 设备关机/休眠或执行器停止

本地任务暂停。云端只能继续原本分配给云执行器的任务；本机文件、浏览器或桌面操作不自动迁移到云端。后台本地服务可减少“关闭窗口即停工”，但不能消除设备断电。

### 首次安装或授权过期

首次企业登记需要联机。授权缓存不被当成无限期通行证；离线访问和执行依据签名包的能力范围、到期时间与企业政策。数据存在、界面可打开和操作被授权是不同状态。

## 5. 防止同一个任务在两处重复执行

任务必须有 placement、ownerDeviceId、attemptId 与执行代次。建议区分 local-bound、cloud-bound、portable-exclusive 三种归属。

- 本地绑定任务在控制中心失联期间仍归原设备；服务端不因心跳缺失就直接另派一台重复执行。
- 可迁移任务通过租约与 fencing token 控制归属；需要权威执行许可的写操作在租约过期后等待续约。
- 草稿和分析可以与对外提交分阶段，分析继续不等于可以越过提交许可。
- 支持幂等的业务 API 使用稳定业务请求键；不支持幂等、且调用结果不明的操作保持 UNKNOWN，先查询回执或人工确认，不自动重放。

心跳只能证明近期连通过，不能单独证明执行器已经停止。网络分区下不能同时承诺“任意节点无限离线写入”“立即撤权”“自动无重复接管”。本方案优先保留本地连续性，同时保守处理不明的外部副作用。

## 6. 心跳与恢复

- 本机巡检不依赖云：检查任务进度、队列、阻塞与执行器健康；检查本身不调用模型。
- 云端心跳与同步独立运行，采用退避与抖动；失败不拖慢本机操作。
- 建议初始运行心跳 30 秒、工作巡检 5 分钟，事件到达立即触发；具体参数经过实测调整。
- 恢复顺序：重新验证设备/授权 → 拉取权威版本与撤权 → 上传本地事件 → 去重/冲突处理 → 核对执行归属和业务回执 → 继续有明确执行条件的任务。
- 角色/权限过期时，低风险本地使用与在线业务写入的规则分别配置。离线窗口越长，撤权传播窗口也越长，应明确选定企业策略。

## 7. 建议第一版可验收标准

1. 完成一次合法登记后，关闭 Naumi 控制中心；已授权本地工作区仍可启动，Bot 身份、人设、缓存记忆与未完任务保留。
2. 控制中心不可达、独立模型路由可达且凭证有效时，本机两个 Bot 完成一次文本派单并回传。
3. 断开模型通道后，界面、记录与队列继续可用；模型步骤显示等待原因，不伪造完成。
4. 离线新增记忆、人设变化与草稿；恢复后去重同步。冲突不覆盖权限或权威事实。
5. 模拟两个执行器和网络分区；相同业务请求不因为丢心跳就被重派，未知副作用保持待核验。
6. 模拟授权过期、撤权及设备时钟变化；不把缓存凭证变成永久授权。
7. 强制退出并重启桌面；已确认持久化事件、消息收据和任务归属恢复。

这些是下一阶段实现与故障注入测试的验收条件，不是对当前版本已经完成的测试声明。
