# 数字员工：日常使用优先交付计划

日期：2026-11-17。决策来源：用户确认企业相关功能次要，先完成日常使用、主动性与可靠执行、员工连续性、工作与交付；企业模块保持当前现状。开工基线 main/origin/main：e620bd982b77bac92d2dc820c83ae2255658d682。

## 新目标与范围

把 Naumi 做成能持续工作的本地数字员工产品：用户通过日常会话和轻量工作入口完成安排工作、后台执行、补充要求、版本化交付、退回/验收与经验复用；员工身份、记忆和任务跨会话/模型/重启保持连续，明确批准的主动工作有边界、可停止、不重复执行。完成隔离真实链路与故障验收后，从固定 main 构建、发布并验证安装/更新。

企业组织、跨产品授权、设备登记、企业共享记忆/同步、集中网关预算与分布式企业执行本期冻结，保持已有源码、接口、数据、配置和开关，不删除、不迁移、不自动启用。统一登录现状保留；它的企业授权扩展不是本阶段前置条件。已有安全与审批边界继续有效。

## 执行顺序与退出条件

| 切片 | 实施重点 | 退出条件 |
| --- | --- | --- |
| D1 日常工作入口 | 复用现有本地目标/版本交付/审核组件与 owner API，普通用户能直接操作，不依赖企业角色或员工中心；保持原聊天、模型位置 | 非企业账号可创建/编辑目标，查看交付版本、退回、逐项验收与关闭；不访问企业业务接口；失败保留输入，冲突不覆盖 |

| D3 工作与交付闭环 | 自然任务与目标/派单/固定版本/人工验收关联，复用原任务账本，不新增平行执行状态 | 同 task 补充要求、退回生成新版本、验收不等于模型结束；文件来源和校验可核验，旧版本仍可打开；批准经验在下个任务可复用 |

| D5 日常候选版交付 | 完整切片集中验证、最新固定 main 打包、Logo/内置插件/浏览器、安装与更新 | 隔离账号/工作区真实使用链路、安装/升级/卸载与数据保留通过；远端安装包与清单哈希一致，旧安装版可更新至候选版 |
| E 后置企业阶段 | 原 M3 与企业相关 M4 扩展、统一身份产品授权/组织设备网关贯通 | D1–D5退出后单独恢复，不把冻结视为已完成 |

D1–D4共同属于第一优先级，顺序为依赖安排，不是把主动性降为次要。工作区历史迁移采用独立审计与可恢复切片；Codex/Claude导入需求保留待办，不混写为已完成。
