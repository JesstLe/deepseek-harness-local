## 1. 产品目标

Bot 是拥有稳定身份、职责、记忆、做事风格、协作关系与可核验交付的数字员工，而不是一条换名会话。

### 核心体验

1. 已有员工可以直接接任务；简单身份创建不再探索源码。
2. 新开会话、切换模型或重启客户端，不丢已持久化的员工身份和长期记忆。
3. 明确的长期偏好能跨任务使用，一次性指令不意外改写长期设定。
4. 主管调用已有员工，不用临时队友冒充现有员工。
5. 员工可主动关注已授权工作，但不通过无意义心跳持续调用模型。
6. 控制中心故障不导致本地资料、记忆、队列与工作区不可用。

### 非目标

- 不伪造人类经历、真实情绪、意识或已完成的业务操作。
- 不把人物设定当授权，不以模型自述代替外部业务回执。
- 不承诺网络分区时无限写入、实时撤权与无重复自动接管同时成立。
- 不把本地测试通过当服务器、跨租户、多设备或安装包上线。

## 2. 用户与角色

| 角色 | 主要操作 | 边界 |
| --- | --- | --- |
| 企业管理员 | 注册组织/设备、岗位、能力、预算、离线政策 | 管理本组织，不跨租户 |
| 直属主管 | 派单、反馈、验收、调整已授权工作习惯 | 不通过一句话提升工具权限 |
| 普通员工 | 与获准 Bot 协作、纠正个人偏好 | 不自动获得组织共享记忆管理权 |
| Bot 执行者 | 检索自身记忆、提出经验/设定候选、报告进度 | 只能基于明确身份和真实来源 |
| 审核者 | 批准/拒绝知识与人物设定变更 | 留审核记录和版本 |

本地现有 owner 登录态只代表单机所有者，不等于企业 RBAC 已实现。云端接入前使用显式 local-owner 数据域，禁止伪造 tenantId。

## 3. 生命周期与状态

### EMP-001 P0 稳定身份（本地＋服务端）
- UUID 与姓名、会话标题分离；一个 Bot 关联多个任务 Session。
- 人物设定、记忆、任务和交付引用稳定 Bot ID；改名不迁移身份。
- 验收：改名/新任务/重启后 ID 不变，历史任务仍可定位。

### EMP-002 P0 在职管理（服务端权威，本地副本）
- 人员状态：draft、active、paused、archived；初始化状态另列 uninitialized、initializing、ready、failed。
- 暂停接新任务不删除会话；归档不自动终止旧任务；终止执行必须明确调用任务取消。
- 第一阶段兼容现有 active/archived，不为 UI 好看强行做数据迁移。
- 验收：暂停/归档对象不接新派单，数据保留，恢复可审计。

### EMP-003 P1 调岗与离职交接
- 职责变更产生岗位版本；未完成任务逐项交接，保留原责任人和新责任人。
- 撤销工具凭证与停用身份分开记录；交付物归组织，不随 Bot 删除。

## 4. 员工档案、性格、人物设定

### PRO-001 P0 基础档案（本地可运行）
- 保存沟通风格 communicationStyle、做事方式 workStyle、性格 personality、人物设定 persona。
- 身份/岗位仍引用 Bot 目录；不重复维护两套名字与职责。
- 首次访问惰性创建空档案，不编造岗位经历、固定性格或人格量表分数。
- 验收：未配置字段为空，不以人设填充暗示不存在的能力。

### PRO-002 P0 显式修改与 CAS
- owner 可逐字段修改；请求携带 expectedRevision，冲突返回 409。
- 每次记录前值/后值、来源、操作者、时间、revision；相同值不重复写入。
- 不接受 model、apikey、approvalPolicy、permission 等越界字段。
- 验收：两次同 revision 写入仅一次成功，工具权限和模型配置不变。

### PRO-003 P0 锁定、自动学习开关
- owner 可锁定具体字段；关闭 autoLearning 后自动规则和模型学习提议停止，手工管理仍可用。
- 锁定字段不被会话自动更新；显式修改也需先解除锁定，不隐式绕过。
- 验收：锁定与关闭学习后输入同样指令，档案不漂移。

### PRO-004 P0 会话驱动成长
- 第一阶段识别单独的明确指令，例如“记住我的偏好：…”“以后回复先给结论”“以后回复简洁直接”。
- 只处理 source.kind=user 的真实文本消息；Agent relay、工具结果、网页、引用资料不作为人物设定指令。
- 以 messageId 去重；长期偏好写入 active memory；明确的回复风格可更新未锁定 communicationStyle。
- 推断性格/其他人设由模型提出 candidate，owner 审核后生效；不实现“模型认为自己变了就直接覆盖”。
- “这一次/本次/暂时”等临时限定不自动固化；复杂混合句第一阶段保持不自动更新。
- 验收：跨会话可见已确认偏好；临时要求、重复消息、relay 和任意工具文本不会污染档案。

### PRO-005 P0 版本恢复
- 恢复历史版本只恢复可配置字段，生成新 revision 与审计事件，不倒退事件序号。
- 需要当前 expectedRevision；与当前锁定字段冲突时拒绝，先解除锁定。
- 验收：恢复后新旧版本均可追溯，人物设定恢复不改变岗位/权限。

## 5. 记忆系统

### MEM-001 P0 分层记忆
- 类别：fact（已知事实）、preference（偏好）、experience（经历）、procedure（方法经验）、relationship（协作关系）。
- 状态：candidate、active、rejected、deleted；过期单独由 expiresAt 判断。
- 工作状态以任务账本为准，不用一条自然语言记忆替代权威执行状态。

### MEM-002 P0 来源与可信边界
- 每条包含 id、botId、kind、text、status、revision、createdAt、updatedAt、source、expiresAt、pinned。
- source 保存 sessionId/messageId/quote 或 owner 显式修改说明；不让 Agent 任意填写可信 user/owner 身份。
- Agent 提案必须引用其当前 Bot 根会话里真实用户消息的原文片段；不存在、越 Bot、非用户来源均拒绝。
- 模型提案默认 candidate，事实不因重复生成变成已确认事实。
- 验收：伪造 messageId、引用其他 Bot、用 relay 冒充用户均失败。

### MEM-003 P0 管理
- 创建、确认/拒绝、修正、固定、设置有效期、逻辑删除、导出均有审计和 CAS。
- 删除后检索和上下文不再包含内容；原始会话与审计保留遵循单独的数据保留策略，不声称物理抹除。
- 不提供“一键从旧版本复活删除内容”；恢复需 owner 明确重新创建。
- 验收：删除后新会话不注入该记忆；过期记录不注入。

### MEM-004 P0 本地检索
- 无网可用；第一版用 SQLite 持久化与本地关键词排序，不把云 embedding 作为启动依赖。
- 限定当前 Bot；先过滤 active/未过期，再按固定项、相关度、新近排序。
- 提供搜索工具和有界上下文注入，查询/长度/条数有上限；无匹配返回空结果，不编造回忆。
- 中文短语可搜索；不执行用户输入的 SQL/FTS 语法。
- 验收：跨 Bot 零泄漏，查询带 SQL 元字符仍为普通检索文本。

### MEM-005 P0 上下文使用
- 当前任务指令高于历史风格；记忆与人设以“历史数据/建议”传入，不作为更高优先级授权。
- 默认注入少量固定和近期 active 记忆；模型按需查询其他记忆，不全量塞历史。
- 密码、令牌、共享主 Key 不写入记忆/人设；明确敏感凭证模式拒绝录入，不能声称自动识别全部秘密。

### MEM-006 P1 企业共享与关系
- 记忆 scope=bot/private、project、organization，由组织 ACL 控制。
- 私人记忆晋升共享需审批；事实冲突保留来源与候选，不按最后写入覆盖。
- 关系描述基于协作事件与验收，不凭空生成“熟悉某员工”或影响权限。

### MEM-007 P1 整理与遗忘
- 任务完成/反馈事件触发候选提取；重复合并、冲突提示、过期清理分阶段执行。
- 摘要与索引可重建；原始事实记录和删除标记有独立保留策略。
- 批量导入先预览数量与来源，不自动扫描全部员工私人文件。

## 6. 心跳、主动性与任务节律

### HBT-001 P0 运行心跳
- 本地一个调度器，默认 30 秒更新运行快照；不为每个 Bot 启一个永久模型会话。
- 快照包含 sampledAt、runtimeState、activeBotCount、runningSessionCount、runningBotCount、staleAfterMs。
- 运行=执行器状态；心跳正常不证明任务有进展，心跳缺失不证明执行已停。
- 由程序完成，0 次 LLM 调用，卸载时清理 timer。

### HBT-002 P0 工作巡检基础
- 默认 5 分钟检查本地执行状态与档案/记忆统计；第一阶段只读观察，不自动重新派单、发布、取消或调用模型。
- 本机事件到达立即更新；timer 防重入、异常后可恢复，错误不伪装成健康快照。
- 每次结果有时间戳；读取 API 不伪造“刚刚心跳”。
- 验收：重复 tick 不产生任务、模型调用或人设变化；模块卸载后无新 tick。

### HBT-003 P1 主动工作
- 基于 owner 批准的 rule：触发事件/时间、Bot、适用范围、行动、预算、工作时间、冷却与幂等键。
- 无事项即静默；模型只参与需要判断的步骤。
- 静默时段不发普通提醒，紧急升级按明确规则。

### HBT-004 P1 长时间无进展
- 最后进展时间与心跳分开；等待用户、等待依赖、模型故障不计成同一种卡死。
- 先检测、再核验、再按策略提示；不因超时直接重复执行未知副作用。

### WRK-001 P1 长期目标与工作队列

- 审核者有身份与权限；退回保留理由；修改创建新交付版本。
- 验收：completed 仅执行结束，不自动变为 accepted；业务验收需明确操作。

### DEL-002 P1 复盘学习
- 由已确认验收反馈生成 procedure/experience candidate。
- 批准后新任务可检索，退回意见和工作事实不混为“性格差”。

## 9. 本地/服务端边界与故障

### LOC-001 P0 本地完整运行时
- 本机保存档案、记忆、会话与任务副本，先落盘、再同步。
- 新增员工结构化数据采用 SQLite WAL；不在本期粗暴迁移已有 bots.json/任务账本。
- 数据路径 `${DSH_HOME}/naumi/employees.sqlite`；不把工作树里的测试数据当员工运行数据。

### LOC-002 P1 同步与事件
- 事件字段：eventId、tenantId/domain、deviceId、aggregateId、baseRevision、kind、source、payload、occurredAt。
- 第一阶段本地仅有审计/outbox 待接入记录，syncState 明确为 local_only，不宣称已与服务端同步。
- 同步按 eventId 去重，删除使用 tombstone；冲突字段保留差异。
- 恢复先拉授权/撤权，再传事件和核对归属，不用旧缓存覆盖权威权限。

### LOC-003 P1 离线授权
- 首次企业登记联机；服务端签发包含组织/设备/范围/能力/期限的授权包。
- 设备密钥与凭证使用 OS 密钥存储；不打包企业主密钥。
- 过期后界面/历史保留与可执行操作分开；离线窗口明确反映撤权传播取舍。
- 时间回拨、撤权、设备复制均有专项测试。

### LOC-004 P1 独立模型通道
- 控制中心与模型网关独立故障域；已有有效凭证不逐句重新登录。
- 网关故障按预授权路由切换；本地模型须显式安装与能力验收。
- 控制中心故障而模型可达：已授权本地 AI 工作继续。
- 所有模型不可达：界面/队列/记录继续，推理步骤等待，不报虚假完成。

### LOC-005 P1 归属与防双执行
- local-bound、cloud-bound、portable-exclusive；记录 ownerDeviceId、attemptId、fencingToken。
- 失联不等于停止，服务端不因丢心跳直接重复分配本机副作用任务。
- 租约到期阻止需权威许可的提交；幂等业务键与 UNKNOWN 状态处理。

### LOC-006 P1 故障注入验收
- 关闭控制中心后本地启动、读取档案、修改偏好、人设版本与记忆检索继续。
- 模型不可达、断网、休眠、强杀重启、离线授权过期、消息 ACK 丢失、同步冲突分别测试。
- 服务恢复后不重复派单/提交；异常业务结果先核验原回执。

### UX-001 P1 员工档案

- 空状态只给必要操作；浅色布局，不加无用标语。

### UX-002 P0 第一阶段可操作入口

- Agent 对明确偏好通过会话事件更新；其他候选由 owner API 管理。
- UI 完整管理页属下一阶段，状态在交付矩阵明确标注。

## 11. API 与工具契约（首阶段）

Base `/naumi/employees`，owner-only，GET/POST；写入需 `x-naumi-employees: 1` 与同源检查，body<=32KiB，严格 schema。

GET query：botId 必填；view=profile/memories/history/export/heartbeat；query、status、limit 有边界。

POST action：profile_update、profile_restore、memory_create、memory_update；botId、expectedRevision、operationId 与动作载荷。

工具：employee_profile、employee_memory_search、employee_memory_propose、employee_profile_propose。

- 工具根据真实 caller 的 root Session 定位 Bot，不收任意 botId。
- teammate 只读本 Bot；写候选仅 Lead；owner 管理不改变现有工具权限。
- 错误码 EMP_*，CAS/幂等冲突=409，身份/来源错误=403，验证错误=400，存储故障=503。
- 新建档案 revision=0；保存后递增。重复 operationId 同载荷返回首次结果，不同载荷拒绝。

## 12. 非功能要求

- 首阶段本地 profile/memory 查询与写入无网络依赖；heartbeat 0 LLM。
- 注入正文上限约 8Ki 字符；记录正文和数量有明确上限，不无界增长上下文。
- 数据写入、审计与待同步事件同 SQLite 事务；失败不返回成功。
- WAL + busy_timeout；事务只包含同步 DB 操作，不跨模型/网络 await。
- 未识别 schemaVersion 或损坏 DB fail closed，不自动重建为空库。
- 本机 SQLite 文件不等于加密存储；组织敏感数据加密、密钥轮转和导出策略列后续安全模块。
- 不输出 API Key、cookie、完整环境变量；证据不复制员工私人聊天全文。
- Git 保留原件 hash、修改副本、差异、验证、可执行回滚；回滚在副本测试，不删运行数据。
